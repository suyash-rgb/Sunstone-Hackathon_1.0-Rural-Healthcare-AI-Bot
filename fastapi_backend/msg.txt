=== Phase 2: LLM & Direct DOM Text Extraction (Targeting the remaining ~52 schemes) ===
- Encountered a limitation where the previous web scraper failed to extract tabbed content because it relied on specific CSS classes (.markdown-content) that were empty upon initial load.
- Attempted to use the Groq LLM API to extract structured JSON data from the scraped webpage body. However, rate limits and token exhaustion made this unscalable.
- Conducted a Root Cause Analysis (RCA) on the website's DOM structure. We discovered that the Next.js Single Page Application (SPA) renders all section text (Details, Benefits, Eligibility, Application Process, Documents Required) directly into the page ody text, regardless of which tab is active.
- Developed a robust line-by-line DOM text parser (parse_myscheme_text) using regex and exact string matching to map section headers directly to the required fields.
- Ran the 
un_clean_extraction.py batch script over the remaining 52 schemes.
- **Result:** Successfully extracted authentic text for 51 out of 52 schemes without using fallback/placeholder strings and without hitting LLM rate limits.
- **Final Null Count:** Only 32 nulls remain in subcategories (as these schemes lack a subcategory on the official portal)
